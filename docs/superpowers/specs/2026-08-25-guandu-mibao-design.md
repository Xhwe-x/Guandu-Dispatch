# 《官渡密报》正式产品与技术设计规格

> 日期：2026-08-25  
> 状态：设计已完成对话确认，等待用户审核规格文件  
> 设计路径：架构级 brainstorming  
> 原型方向：方案 A——双环情报推理

## 1. 产品定义

《官渡密报》是一款单人、2D、桌面横屏的情报推理与反情报决策游戏，面向 PC/Web。

玩家调查上一支粮队的碎片化泄密链，再利用同一组情报渠道投放假信息，根据敌军行动验证判断，最后决定将完整真相交给哪一方。

核心循环：

```text
阅读文书
→ 提取主张
→ 找出矛盾
→ 建立泄密假说
→ 选择有限调查
→ 用证据审讯
→ 还原信息链
→ 按渠道投放诱饵
→ 观察敌军反应
→ 修正判断
→ 提交最终汇报
→ 决定真相归属
→ 生成政治尾声
```

原型内容量以 20–30 分钟为目标，但不限制玩家实际游玩时间。阅读、思考、查看地图和整理关系板均不限时，只有玩家主动确认后才推进阶段。

## 2. 设计目标

首个原型只验证一件事：

> “先理解敌人如何获取信息，再用同样的机制欺骗敌人”是否足够好玩。

成功的测试玩家应当能够：

- 主动比较不同文书并发现矛盾；
- 从“寻找偷走完整粮册的人”转向分析信息权限与传播链；
- 区分违法、撒谎、受胁迫泄密和主动通敌；
- 理解多条真实碎片可以组合成致命军情；
- 解释为什么要向不同渠道投放不同类型的假信息；
- 根据敌军反应修正判断；
- 独立复述完整泄密链；
- 区分行动成败与政治立场。

如果体验退化为“依次阅读剧情后选择答案”，则核心玩法没有成立。

## 3. 世界观与玩家身份

世界借鉴汉末的驿传、粮运、商路、印信和军阀战争，但人物、势力和事件全部架空。

### 3.1 势力

- **沧河军**：控制官渡驿站的东部势力，强调军令和秩序，但可能牺牲地方利益。
- **朔原军**：从西面推进的敌对势力，擅长利用商旅与民间信息网络。
- **官渡里社**：由驿传旧吏、地方长者、商户和村民代表组成的松散地方组织。

普通界面和对白可以使用“东军”“西军”“地方”作为简称；正式文书和政治结尾使用完整名称。

### 3.2 玩家

玩家是一名没有固定姓名和性别的汉廷旧吏，熟悉驿传规则、粮册、桥梁、商路、印信、马匹和车辆。

汉廷权威已经衰落。沧河军因玩家熟悉本地制度而临时委托其调查，但并不完全信任玩家。玩家不天然效忠任何一方，结尾可以自主决定真相归属。

## 4. 核心主题

核心主题为：

> 信息的危险不只在真假，也在谁能接触、拼合和利用它。

前半段让玩家认识到，多条真实但不完整的信息可以组合成致命军情；后半段让玩家认识到，不必伪造每项事实，也可以通过安排信息的可见范围诱导敌人得出错误结论。

## 5. 固定案件真相

没有人偷走完整粮册，也没有任何一名嫌疑人独自掌握完整运输命令。

固定真相为：

```text
赵简因家人受胁迫，向杜衡泄露粮队出发时辰
＋
杜衡从草料采购、车轮规格、北桥维修和商路变化推断路线
＋
杜衡使用商品价格表暗号，将拼合后的情报传给朔原军
＝
朔原军获得伏击所需的路线与时辰
```

粮队规模由杜衡从草料和车辆情况中推断，用于证明其情报分析能力和补强路线判断，但不是伏击成立的第三个必要条件。

## 6. 四名核心人物

| 人物 | 身份与权限 | 隐瞒或谎言 | 案件责任 |
| --- | --- | --- | --- |
| 陆淳 | 驿丞；接触粮册、印信和驿马调度 | 挪用少量军粮救济村民并修改数量 | 违法但未通敌 |
| 郑禾 | 粮官；接触粮车规模和车辆损坏记录 | 修改维修记录掩盖工作失误 | 撒谎但未泄露核心情报 |
| 赵简 | 传令书吏；抄写集合命令，知道出发时辰 | 声称不知道时辰 | 受胁迫泄露时间 |
| 杜衡 | 商人；接触采购、车轮、桥梁和商路迹象 | 伪装成普通供应商 | 推断路线、拼合并传递情报 |

四人的设计作用分别是：

- 陆淳：做了坏事的人不一定是内奸；
- 郑禾：说谎不等于通敌；
- 赵简：泄密者也可能只掌握一块碎片；
- 杜衡：真正危险的人不一定接触正式军令。

## 7. 体验阶段

游戏分为六个内容阶段。阶段只表示进度，不构成时间限制。

1. **伏击后的文书**：玩家收到军报、粮册、维修记录、口供和路线图，形成“完整粮册被盗”的初始假说。
2. **人人都有秘密**：玩家发现四人都不完全诚实，但谎言性质不同。
3. **没有完整内奸**：玩家确认无人掌握完整路线，转向还原信息传播链。
4. **多渠道信息投饵**：玩家制定真实粮运计划，并向四个渠道投放权限一致的假信息。
5. **敌军反馈与最终汇报**：玩家根据斥候报告修正关系板并提交结论。
6. **真相归属与政治尾声**：行动结果确定后，玩家选择真相最终属于谁。

每次阶段推进均由玩家主动触发，并展示即将锁定的选择摘要。

## 8. 文书与主张卡

每份文书约 80–180 字，优先使用短军报、账册、维修记录、商旅记录和人物口供。

玩家从预设的关键语句中提取主张卡。主张卡记录：

- 主张文本；
- 来源文书；
- 涉及人物、时间、地点和事件；
- 可以建立的关系类型。

系统不使用自然语言理解。文书保留完整原文，主张卡承担实际推理交互。

基础证据包括：

- 原始粮册与修改粮册：证明陆淳篡改数量，但不能证明其知道路线或时辰；
- 车辆记录与实际损坏：证明郑禾撒谎，但其权限不足以造成精准伏击；
- 赵简亲笔集合命令：反驳“赵简不知道出发时辰”；
- 草料采购、车轮规格和北桥维修：证明杜衡能够推断运输路线；
- 异常商品价格表：证明情报通过商旅渠道离开驿站。

## 9. 情报关系板

关系板采用“固定逻辑槽位＋证据自由拖放”。

核心槽位为：

```text
泄露的信息
→ 信息来源
→ 接触人物
→ 推断或传递方式
→ 敌军获得的结论
```

支持的关系类型为：

- 支持；
- 反驳；
- 来源于；
- 接触过；
- 推断出；
- 传递给。

系统根据稳定 ID、证据标签和关系类型判定，不要求唯一布局，也不分析自由文本。

## 10. 调查点

玩家拥有固定 3 个调查点，可以从以下六项中选择：

1. 检查印信与笔迹；
2. 深查杜衡的采购和价格记录；
3. 复查北桥维修情况；
4. 查询赵简家人；
5. 重勘伏击地点；
6. 深入审讯一名人物。

常规审讯中的“口供＋矛盾证据”交互不消耗调查点；第 6 项“深入审讯”是额外调查行动，用于解锁普通质询无法获得的动机或背景信息。

基础文书足以建立“赵简泄露时间、杜衡推断路线”的主假说。

正确使用两个调查点即可证明主真相；第三个调查点用于确认赵简受胁迫、找到价格表暗号、排除无辜人物或获得更好的角色结局。

调查点限制选择数量，不限制玩家思考时间。

## 11. 审讯

每次审讯分为三步：

```text
选择人物口供
→ 提交与之矛盾的证据
→ 选择审讯态度
```

审讯态度包括冷静、威慑、怀柔和诱导。

证据决定能否突破口供；态度只影响透露的信息量、人物状态和附加对话，不能替代证据。

错误提交不会导致立即失败，但会使人物从“合作”转为“戒备”或“敌对”。必要的主线证据不会永久消失，错误主要影响可选信息、人物命运和最终评价。

## 12. 提示系统

提示只能由玩家主动请求，分为三层：

1. 指出调查方向；
2. 指向相关人物或文书；
3. 明示具体矛盾。

使用提示不会导致机械惩罚，但可在结算统计中记录，供原型测试分析。该统计只保存在当前本地存档中，不上传到服务器。

## 13. 多渠道信息投饵

调查结束后，玩家同时制定第二支粮队的真实路线与时辰，并向四个渠道分别投放一种符合其权限的假信息。

| 渠道 | 信息类型 | 预设投放方式 |
| --- | --- | --- |
| 陆淳 | 假驿传调度 | 驿马调用、盖印顺序、通行优先级 |
| 郑禾 | 假粮队规模 | 空车、粮袋登记、车辆编组 |
| 赵简 | 假出发时辰 | 临时集合文书、值夜安排 |
| 杜衡 | 假路线迹象 | 草料采购、车轮规格、桥梁与空车动向 |

赵简的假时辰和杜衡的假路线属于两条核心诱饵，直接决定朔原军是否获得有效伏击条件。陆淳和郑禾的诱饵用于验证正式驿传与车辆记录是否也是泄密渠道，但不单独决定伏击地点与时辰。

每个渠道提供数个预设诱饵，玩家各选一个。选项具有公开、可检查的可信条件，不使用隐藏概率。

例如，要让杜衡相信粮队走北桥，诱饵必须同时符合北桥承重、车轮规格和采购量。玩家已经在前半段接触过这些规则。

## 14. 敌军反馈

敌军行为完全由固定案件真相和诱饵可信度决定，不使用随机数，不主动实施欺骗性假动作，也不会因为玩家猜对而临时改变规则。

示例投饵：

```text
陆淳：南线调用驿马
郑禾：登记三十六辆粮车
赵简：寅时集合
杜衡：制造北桥运输迹象
```

斥候报告朔原军轻骑在北桥附近出现，并于寅时前集结，即支持“赵简的时间渠道＋杜衡的路线渠道”。南线驿马和三十六辆粮车未反映在敌军行动中，不支持陆淳或郑禾参与核心泄密。

玩家收到报告后可以修改关系板和最终判断，但不能重做本次行动。

## 15. 最终汇报

玩家需要回答：

1. 泄露了什么；
2. 信息分别来自谁；
3. 谁负责拼合并传递；
4. 信息如何离开驿站；
5. 建议如何处理相关人物与渠道。

每项关键结论至少附上一张支持证据。

系统分别判断：

- 结论是否正确；
- 证据是否真正支持结论；
- 是否错误指控陆淳或郑禾；
- 是否查明赵简受胁迫；
- 是否找到商品价格表暗号。

## 16. 三档行动结果

### 16.1 封网成功

玩家正确还原核心泄密链，两条核心诱饵均生效，并查明主要传递方式。第二支粮队安全，情报网络可以被切断或反向利用。

### 16.2 保粮失人

至少一条核心诱饵生效，使第二支粮队获救；但玩家漏掉部分泄密链、未找到价格表暗号，或错误牵连陆淳、郑禾。即使两条核心诱饵都生效，错误汇报也会落入本档。战术目标完成，但网络仍有残余。

### 16.3 再次伏击

两条核心诱饵均未生效、真实计划暴露，或核心判断严重错误时，朔原军继续获得有效信息，第二支粮队再次遭伏击。

错误产生剧情后果，不进入“判断错即 Game Over”的循环。

## 17. 真相归属与政治结尾

行动结果确定后，玩家选择完整真相的归属：

- **交给沧河军**：维护军事秩序，最可能彻底清除网络，但所有违法行为都可能被追究；
- **交给朔原军**：选择阵营利益和新的政治身份，但背叛当前控制者，并可能牺牲后续粮运与地方利益；
- **交给官渡里社**：优先保护村民、商路和受胁迫者，但不能彻底控制军事情报网络；
- **销毁关键证据**：拒绝让任何势力掌握完整网络，但核心人物可能逃脱，玩家独自承担责任。

政治选择不能修正错误推理，也不能改变已经发生的粮运结果。

尾声由四层组合：

```text
行动结果
＋
真相归属
＋
四名人物命运
＋
玩家自身处境
```

人物命运根据证据、错误指控、胁迫事实、处理建议和真相归属生成，不需要手写十二条完全独立剧情。

## 18. 公平推理与错误原则

每个重要错误结论都必须存在事前可见的反证。允许使用时间冲突、权限不匹配、印章异常、用词变化、地图距离、采购异常、车辆规格和口供矛盾。

禁止：

- 无迹可寻的临时策反；
- 完全随机的关键谎言；
- 结尾才出现的关键人物；
- 临时增加新规则；
- 只能依靠猜测的核心答案；
- 玩家不可能提前获得的信息；
- 第一案中的敌军假动作。

结局复盘必须指出玩家遗漏的可见证据。

## 19. 界面设计

采用“三栏情报桌”布局。

### 顶部

- 当前阶段；
- 剩余调查点；
- 当前目标。

不显示时间或阶段倒计时。

### 左侧：情报匣

- 军报；
- 粮册；
- 口供；
- 维修记录；
- 商旅记录；
- 调查结果。

支持按人物、时间和来源筛选。

### 中央：工作区域

- 文书桌；
- 情报关系板；
- 官渡路线图。

文书在中央打开，不使用遮挡整个界面的弹窗，方便同时查看人物档案。

### 右侧：人物档案

- 四名人物；
- 已有口供；
- 已知秘密；
- 已发现矛盾；
- 合作、戒备或敌对状态。

### 底部：操作

- 调查；
- 审讯；
- 信息投饵；
- 最终汇报；
- 提示。

拖拽不合法时，卡片返回原位并说明原因。结束调查、执行投饵和提交汇报前必须展示选择摘要并二次确认。

## 20. 美术与声音

第一版人物使用剪影、姓名、职位和一个标志物：

- 陆淳：印信；
- 郑禾：粮袋；
- 赵简：笔与军令；
- 杜衡：算盘或商袋。

整体使用米黄色纸张、墨迹、红色印章、线稿地图、磨损和烧焦边缘，不制作人物动画、正式过场或完整立绘。

声音包括翻纸、毛笔、印章、木桌、风声、马蹄、远处战鼓、军号和夜间环境声。声音必须有对应视觉反馈。不制作配音或复杂动态音乐系统。

## 21. 技术架构

技术栈：

- React；
- TypeScript；
- Vite；
- 浏览器本地存档；
- 无服务器；
- 无账号；
- 无数据库。

数据流：

```text
案件内容数据
→ 游戏状态
→ 推理与结局规则
→ React 表现层
→ 浏览器本地存档
```

### 21.1 案件内容模块

保存人物、文书、主张、证据、调查、审讯、投饵、敌军反馈和结局文本。所有实体使用稳定 ID 建立关系。

### 21.2 游戏状态模块

保存当前阶段、调查点、已读文书、已提取主张、关系板、人物状态、投饵、汇报和政治选择。

### 21.3 规则模块

验证证据链、诱饵可信度、敌军反馈、三档行动结果和尾声标签。规则模块不直接控制界面。

### 21.4 表现模块

负责三栏情报桌、文书、地图、关系板、人物档案、审讯、投饵和尾声。

### 21.5 存档模块

在关键选择后自动保存，并在阶段推进前保留一个有效快照。恢复旧快照会明确提示将丢弃其后的进度。

案件内容与程序分离，但首个原型只制作《官渡密报》一案，不提前开发案件编辑器。

## 22. 数据与异常处理

- 启动时验证案件数据中的缺失引用、重复 ID 和矛盾条件；
- 运行时不把数据错误包装成玩家推理失败；
- 存档包含结构版本号；
- 存档损坏时优先恢复最近有效快照，不静默覆盖；
- 无法恢复时明确说明原因，并允许开始新游戏；
- 阶段推进前展示将被锁定的选择；
- 不使用自然语言判定、隐藏概率或随机真相。

## 23. 验证与测试

### 单元测试

- 证据关系判定；
- 主张与来源引用；
- 诱饵可信条件；
- 敌军反馈组合；
- 三档行动结果；
- 尾声标签组合；
- 存档序列化、恢复和版本处理。

### 集成测试

- 完整跑通封网成功；
- 完整跑通保粮失人；
- 完整跑通再次伏击；
- 验证四种真相归属不会修改既有行动结果；
- 验证错误审讯不会永久删除必要主线证据；
- 验证阶段只在玩家主动确认后推进。

### 内容检查

- 每个关键结论都有事前证据；
- 每个重要错误结论都有可见反证；
- 所有文书权限与人物身份一致；
- 投饵渠道与前半段信息权限一致；
- 结局复盘能够解释玩家的错误。

### 玩家测试

观察玩家是否主动比较文书、修正假说、理解投饵机制、复述泄密链，并能说明政治选择理由。

## 24. 明确非目标

首个原型不包含：

- 多人联机；
- 战斗和角色养成；
- 大地图和历史名将系统；
- 随机真相或动态案件生成；
- 多案件选择；
- 敌军反反间；
- 多阵营开局和独立主线；
- 长期政治、外交或声望系统；
- 云存档、账号和数据库；
- Steam 功能和商业化；
- 手机适配；
- 正式人物立绘、配音和复杂过场；
- 案件编辑器；
- 自由沙盒式谍报模拟。

## 25. 原型完成标准

原型完成必须同时满足：

1. 玩家能够从头到尾完成一局；
2. 三个行动结果均可通过确定规则到达；
3. 四种真相归属均生成连贯尾声；
4. 关系板、调查、审讯和投饵共同参与推理，不退化为单纯选项问答；
5. 没有机械时间限制或自动阶段推进；
6. 基础文书足以建立主假说；
7. 错误能够产生可解释的剧情后果；
8. 存档和阶段快照能够恢复有效游戏状态；
9. 测试玩家能够解释“赵简泄露时辰＋杜衡推断路线并传递”的完整链条；
10. 原型范围没有扩张到第 24 节的非目标。
