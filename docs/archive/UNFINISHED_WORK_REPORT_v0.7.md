# 《官渡密报》v0.7 未完成工作报告

> 用途：对 v0.7 实际交付状态做客观盘点。只有玩家在正常流程中真正能看到、能操作、能恢复的功能才记为“已完成”。
> 更新基线：2026-08-27 / v0.8 重构前审计。

## A. v0.7 已完成

- 第一案从序章、军帐、军报、笔迹、赵简审讯、第一层推理、四匣并查、双渠道推理、投饵、敌军回声、最终报告到结局的规则链已经存在。
- 曹操两次阶段复命的数据和基础 `AudienceScene` 已接入主流程。
- 赵简、陆淳、郑禾、杜衡已存在人物—文书—线索—任务关联数据。
- 基础案卷导航、任务提示、情境教程、Web Audio 提示音和浏览器短语音原型已经存在。
- v0.7 使用状态版本 3 保存场景、剧情位置、调查、审讯、推理、曹操复命等数据。

## B. v0.7 部分完成

### 人物对白表现
- 有 `CharacterPortrait`，但大部分人物仍是程序化 SVG，占位感较强。
- 赵简初问有立绘，但不是“一句对白一张人物卡”的通用系统。
- 曹操觐见有双人物画面，但按钮、对话框、人物切镜仍偏网页控件。

### 音效
- 有点击、确认、纸张、入帐、警告、任务解锁等合成提示音。
- 有“参见主公 / 臣领命”等浏览器 TTS 原型。
- 尚未形成按控件语义、人物入场、证据落案、推理连线等完整声音词典。

### 案卷 / 防卡死
- 有返回、案卷、当前任务、提示入口。
- 但导航历史只保存 `sceneId`，没有保存 `storySceneId + beatIndex`；因此返回或旧存档可能恢复到场景外壳而不是准确对白节点。
- v0.7 对 version 3 存档只做 schema 校验，不会再次校正 presentation 兼容性。

### CG
- 序章以 SVG/CSS 演出为主。
- 曹操大帐、审讯、调查仍以 CSS 和程序化人物为主体；没有统一正式 CG 资产管线。

## D. v0.7 需要返工

### 1. 场景恢复
截图中出现的：

> “当前场景 ‘dialogue’ 的数据未能正确载入”

说明 v0.7 仍会把技术 fallback 暴露给玩家。根因是 presentation 中 `sceneId` 与 `storySceneId` 可以不匹配，且 version 3 存档不会再次迁移。

**v0.8 处理：**状态升级到 v4；保存完整导航快照；每次加载和场景切换校验 scene/story 兼容性；普通玩家只看到“案卷记录恢复”。

### 2. 控件系统
v0.7 大量 `scene-button`、普通 `<button>`、圆角卡片仍然具有 Web UI / Dashboard 感。

**v0.8 处理：**建立 command / secondary / tool / danger / locked / choice / evidence 七类控件，统一军令、题签、案牍视觉与点击音效。

### 3. 人物与对白
v0.7 多数场景是“人物图 + 独立文字框”，人物没有随每一句话真正切镜。

**v0.8 处理：**新增 `DialogueCharacterCard`、统一 speaker metadata，赵简初问、军帐议事、四匣人物、审讯结果全部进入人物卡表现。

### 4. CG / 美术
v0.7 正式场景资源不足，CSS 几何图形仍承担太多最终视觉职责。

**v0.8 处理：**接入 ImageGen 生成的 v0.8 概念美术并制作游戏安全裁切；首批覆盖曹操大帐、夜袭、赵简审讯、案桌，并保留 2.5D 光影叠层。

## v0.8 关闭本报告的标准

以下项目只有满足时才从“未完成”移出：

1. `dialogue` 旧存档可恢复并实际出现人物卡。
2. 返回可恢复到具体剧情 beat。
3. 曹操、赵简、郑禾、杜衡、陆淳在玩家流程中实际有可见人物表现。
4. 主操作按钮不再使用默认/普通网页按钮语言。
5. 案卷至少具备人物、密报、证据、推理、任务、教程、设置七个实际页签。
6. 关键操作存在可听声音反馈。
7. 运行时不向玩家显示 `sceneId`、`storySceneId`、placeholder、prototype 等开发术语。
